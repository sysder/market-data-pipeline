# 決定

- クラウド: AWS EC2
- OS: Ubuntu 26.04 LTS
- インスタンス: t4g.micro（ARM系CPU、2vCPU、1GB RAM）、ディスクは8GB
- アカウントは有料プラン（従量課金）

# 理由

クラウド（AWS）:

- シェア首位で情報量が最も多く、経験の可搬性が高い
- GCPの無料枠VMと比較したが、月数百円の差より上記を優先した

OS（Ubuntu 26.04 LTS）:

- サーバ用途で最も普及しており、詰まったとき検索で解決しやすい（Amazon LinuxはAWS外で通用しない）
- 26.04はLTS（サポート2031年まで）。収集サーバは立てたら長く回すので期限の長い方を選んだ

インスタンス（t4g.micro）:

- t4g（ARM）は同格のx86系より約2割安い。ポーラーは純PythonなのでARMで問題なく動く
- 要求リソース的には最小クラスで足りる見込みだが、コンソールの選択肢の最小がmicroだった
- 負荷はsleep主体のポーラー2本のため、CPUほぼゼロ・メモリ数十MBの見込み（稼働後に実測して更新する）

# 費用とプラン

- 月額見込み: 約2,000円（EC2 約$8 + パブリックIPv4 約$3.7 + EBS 約$0.8。2026-07時点の概算）
- 予算で月$20超の警告を設定済み

# セキュリティ

- SSH(22番)は自分のIPからのみ許可

# 再検討条件

- Phase1の板ストリーム収集で負荷・ディスク消費が増えた時、インスタンスサイズと構成を見直す
- 場所の移動でSSH不通が頻発するようになったら、SGのIP更新の運用を見直す
